# 패킷과 접수

## 패킷 입력

개인 자료는 작업 트리 밖에서 준비한다. 기본 작업 폴더는 `${JOBSTACK_STATE_DIR:-$HOME/.jobstack}/personal-career/<JOB_ID>/`로 두고 그 아래에 `input/`과 `evidence/`를 나란히 둔다. 지원 건마다 공고판·공고 번호를 함께 식별할 수 있는 안정적인 `JOB_ID`를 정해 재개에도 같은 ID를 쓴다. ID는 ASCII 영문·숫자로 시작하고, 영문·숫자·하이픈·밑줄을 합쳐 최대 80자로 쓴다. 공고 식별자가 없으면 회사·직무·공고 URL을 대조해 기존 ID와 중복되지 않는지 확인한다. 접수 증거, 문항 출처 검토표, 중간 파일은 패킷 입력 밖에 둔다.

입력 디렉토리에는 `job.json`, `answers/`, 필요한 경우 `attachments/`를 일반 파일과 디렉토리로 둔다. `job.json`의 `id`는 명령의 `JOB_ID`와 일치해야 한다. 다음 예시의 `example.invalid`는 형식 설명용이다.

```json
{
  "id": "example-backend-1234",
  "company": "예시 기업",
  "position": "백엔드 개발",
  "board": "예시 채용 사이트",
  "posting_url": "https://example.invalid/jobs/1234",
  "application_url": "https://example.invalid/jobs/1234/apply"
}
```

`answers/`에는 폼 입력값·선택값과 문항 대응을 재현할 수 있는 최종 파일을 하나 이상 둔다. 서술형 문항에는 복사할 답변 본문을 그대로 두고, 폼의 기타 값·자동 입력 프로필·동의·첨부가 어느 필드에 들어가는지는 별도 항목으로 기록한다. 서술형이 없는 폼도 선택할 이력서와 필드별 입력·선택값을 기록한다. 개인 연락처 등은 실제 제출에 필요한 값만 담는다. URL은 세션 토큰과 인증 정보가 없는 주소를 기록한다. `attachments/`에는 실제 업로드할 최종 파일만 복사한다. CLI가 시도 직전 입력 디렉토리도 검사하므로 승인한 입력은 `ready`가 성공할 때까지 그대로 둔다.

## 로컬 명령

아래에서 `$PACKET`은 이 포크의 `bin/jobstack-packet` 절대 경로다. Bash에서 기존 프리앰블의 환경을 읽었다면 `$_JS_BIN/jobstack-packet`을 사용할 수 있다. `$INPUT_DIR`, `$JOB_ID`, `$REVISION`에는 해당 건의 값을 넣고, `$ATTEMPT`에는 `ready` 또는 `status`가 응답한 현재 `attempt` 번호를 넣는다. 명령은 JSON으로 결과를 반환한다. 상태는 `JOBSTACK_STATE_DIR`(기본 `~/.jobstack`) 아래 `packets/`에 저장한다. 상태 루트를 지정할 때는 모든 명령에 같은 `--state-dir ROOT`를 서브커맨드 앞에 둔다.

```bash
"$PACKET" snapshot "$JOB_ID" "$INPUT_DIR"
"$PACKET" status "$JOB_ID"
```

`snapshot`의 `revision`과 `snapshot_path`를 확인한다. 사용자에게 **그 경로의 실제 내용**을 열어 검토할 수 있게 제공한다. 회사·직무·공고판·공고 URL·지원 사이트, 필드/문항별 정확한 입력과 선택값·공개 범위·동의 항목, 내는 첨부 이름과 실제 파일 경로를 모두 포함한다. 긴 문장과 파일은 실제 검토본을 제공한다. 변경이 있으면 입력을 고치고 새 스냅샷을 만들어 바뀐 부분과 전체 검토본을 다시 제시한다.

사용자가 검토한 리비전을 명시적으로 승인한 뒤 해당 값을 기록한다. 승인과 제출 허용은 같은 메시지에서 각각 명시할 수 있다. 예를 들어 `example-backend-1234의 리비전 <리비전> 내용을 승인합니다. 제가 직접 제출하겠습니다.` 또는 `example-backend-1234의 리비전 <리비전> 내용을 승인합니다. 이 공고의 최종 제출 버튼을 한 번 눌러 주세요.`로 범위를 특정한다.

```bash
"$PACKET" approve "$JOB_ID" "$REVISION"
```

## 한 번 제출하고 성공 증거 보관

1. **브라우저 준비.** 수동 제출은 동결본과 필드별 복사·첨부 안내를 사용자에게 제공한다. 에이전트 제출은 사용자가 지정한 브라우저 또는 로컬 브라우저 도구로 화면을 준비한다. 입력, 첨부 또는 다음 단계 이동만으로 서버에 전송·저장되는 화면은 해당 동작에 대한 사용자 허용을 먼저 확인한다. 로그인·인증·CAPTCHA와 미승인 동의는 사용자가 직접 처리한다. 중간 화면에서 다른 공고나 사이트로 바뀌면 대상을 확인하고, 승인 내용과 달라진 항목에는 새 스냅샷을 검토받는다.
2. **직전 대조.** 마지막 화면에서 제출 대상, 실제 필드 값, 첨부 이름과 동결본에서 선택한 파일, 공개 범위·동의, 최종 제출 버튼 라벨을 대조한다. 수동 진행의 화면에 접근할 수 없으면 사용자가 동결본과 대조한 뒤 제출 직전임을 확인하도록 한다. 원본 입력 디렉토리의 파일 대신 `snapshot_path`에 반환된 파일을 사용한다.
3. **한 번의 시도.** 형식적으로 승인된 것만으로 `ready`를 실행하지 않는다. 선택된 제출 주체가 즉시 제출할 준비를 끝낸 때 아래 명령을 호출한다. `ready`는 리비전과 동결 파일을 검증하고 한 번의 시도를 확보한다. 성공 후 사용자가 직접 최종 버튼을 누르거나, 명시적 1회 허용이 있는 에이전트가 해당 화면에서 한 번 클릭한다. 실제 클릭 없이 저장 명령을 실행하는 것만으로 접수 완료 상태를 기록하지 않는다. 사용자가 이미 제출했다고 하면 다시 클릭하거나 과거 시도를 꾸미기 위해 `ready`를 실행하지 않는다.

   ```bash
   "$PACKET" ready "$JOB_ID" "$REVISION"
   ```

4. **접수 확인.** 성공 화면, 공식 지원 내역, 해당 접수 메일에서 공고와 접수 사실을 대조한다. 접수 번호가 있으면 포함하고, 증거 원본 또는 필요한 부분을 패킷 입력과 저장소 밖의 비어 있지 않은 로컬 파일로 저장한다. `$CONFIRMATION`은 확인된 접수 문구나 번호, `$EVIDENCE`는 그 파일 경로다. 절차를 통해 확보한 시도의 성공을 확인한 경우에만 기록한다.

   ```bash
   "$PACKET" receipt "$JOB_ID" "$REVISION" --attempt "$ATTEMPT" --success \
     --confirmation "$CONFIRMATION" --evidence "$EVIDENCE"
   "$PACKET" status "$JOB_ID"
   ```

5. **증거가 모호한 경우.** 타임아웃, 네트워크 단절, 명시적 성공 문구가 없는 리다이렉트는 접수 미확인이다. `status`로 남아 있는 시도(`pending`)를 확인하고 공식 지원 내역·메일을 확인한다. 성공 증거가 나오면 기존 시도의 접수만 기록한다. 해당 시도가 제출되지 않았다는 공식 답변이나 화면을 확보하기 전에는 `pending`을 유지한다. 새 ID, 다른 브라우저, 재클릭으로 같은 지원을 반복하지 않는다.

6. **제출되지 않았음이 확인된 경우.** 해당 시도에 대한 공식 확인을 파일로 보관한다. 예를 들어 최종 버튼을 누르기 전에 사용자가 취소했다면, 클릭하지 않았다는 확인과 해당 공고가 아직 미제출 상태임을 보여주는 포털 화면을 함께 보관한다. 화면 로딩이 지연되거나 공고를 특정할 수 없으면 접수 여부를 계속 확인한다. `$REASON`에는 확인 근거의 요지를 넣고, `$EVIDENCE`에는 해당 시도의 증거 파일을 지정한다. `failed`는 그 시도를 기록하고 이전 승인을 해제한다. 사용자에게 결과를 전달하고, 다시 진행하려면 같은 지원 ID에서 내용을 다시 검토해 새 승인을 받는다. 내용이 바뀌면 새로 스냅샷을 만든다. 에이전트가 제출하는 경우 다시 시도할 때도 명시적 1회 제출 허용이 필요하다.

   ```bash
   "$PACKET" failed "$JOB_ID" "$REVISION" --attempt "$ATTEMPT" --not-submitted \
     --reason "$REASON" --evidence "$EVIDENCE"
   ```

접수 결과와 입증 자료는 로컬에 둔다. 사용자가 이 절차 전에 직접 접수한 경우 증거를 바탕으로 설명하고 학습 계획을 준비할 수 있다. 당시 제출 파일을 확인해야 확정 제출본으로 인용할 수 있다.
